# Game logic and server rules

- Built-in category presets live in a browser-safe constants module alongside a deduplicating merge helper; shared saved lists remain database-backed so built-ins require no migration or page-load seeding.
- Round selection uses a shuffled least-recently-used category pool capped at eight, so unused categories are exhausted before repeats.
- Results reuse round ends_at as a server-issued viewing deadline and shared pacing constants; startNextRound validates the host session, expected round and readiness/override before advancing or ending to keep multiplayer transitions authoritative without changing the schema.
- Independent server reads and score writes run in parallel with at most six outbound requests per batch to respect the deployed runtime budget.
- Training bots are `party_players.is_bot` rows with no session, driven by a host-device heartbeat (`tickPartyBots`) with deterministic per-bot delays (`party-bots.ts`); their AI/fallback content is cached in party_private at round_number = -round so it never races round data, and bots never become host or keep a room alive.
- Stop "Recorrer ao Juiz" lives in public_state.appeal during reveal (rules in `stop-appeal.ts`), is version-guarded, and must settle before the next round.
- Final rankings use a browser-safe competition-rank helper so equal totals share a place without changing stored scoring rules.
- Party transitions are version-guarded, recompute submissions from the table and keep scores inside public_state, so concurrent advances resolve once; party AI prompts stay isolated in `party-ai.server.ts` with built-in fallbacks; with the AI judge (Tribunal/Debate/Roleta, `effectiveJudgeFor`) the AI only chooses among neutrally labelled entries via a version-claimed `evaluating` phase, points come from the deterministic engine, and failures fall back to a group vote (a Tribunal duel draws instead) so rounds never stall; podium AI awards are written to public_state after "final", so the ranking never waits on them.
- Stop's AI judge lives only in `stop-judge.server.ts`, shared by both Stops so they judge identically; scoring mode and intensity are host room rules (`PartySettings`), not developer settings.
- "Rei da Noite" reuses `party_players.score`, added only by the caller whose version-guarded update ended the match, so nothing double counts.
- Group-room presence is a 30s session-verified heartbeat (`touchPartyPresence`, throttled server-side); `party-presence.ts` decides who counts (3-minute window, bots always) for starts, new-round seats and "everyone done", and never deletes players, so blips and app switches cost nothing.
- Room transitions claim the version-guarded room update first and clear round rows only afterwards; room creation/join compensate partial inserts, retry code collisions on the UNIQUE constraint, and are rate-limited per network address in server-only `party_rate_events`.
- Roleta respond submissions carry the challenge key (skips counter) and every read filters by it, so answers to a skipped challenge never leak into the next one even if cleanup fails.
- Player-facing error toasts go through `friendlyError` (`friendly-error.ts`) so server messages written for players pass through while validation dumps, network and database details become plain guidance.
- Every party/Stop AI call goes through `withAiCredit` in `party.server.ts` with a usage key derived from the triggering room version, so racing or repeated calls charge once, failures refund, and an empty wallet throws `NoAiCredits` into the existing non-AI fallbacks (Stop cannot start at zero); the AI modules themselves stay untouched.
- Credit wallets belong to an account (`user_id`) or a hashed server-issued guest token; free credits are granted once per wallet/account via unique ledger references and limited per network per day; `credit_merge` moves a guest wallet into an account atomically (only bought credits when the account already has one).
- Purchases: `payments.server.ts` records a transaction, verifies the Play purchase token with the Developer API (`google-play.server.ts`, service-account secret), grants once per store order id, consumes on the store, and admin reconciliation re-checks pending ones and applies voided-purchase reversals without deleting history.
- Commercial and moderation tables (wallets, ledger, usage, billing, payments, audit, reports, admin invites) have no client grants; only server functions touch them. Admin roles come from `user_roles` (first admins via the server-only `admin_invites` email list on confirmed sign-up).
- Free-form AI endpoints without a room balance (score explanations, the AI lab) are admin-only; game payloads are size-capped in `party-input.ts` and shared category lists are saved only through a rate-limited server function.
